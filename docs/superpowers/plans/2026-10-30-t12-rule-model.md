# T12 Rule Model Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make TLS-001, LINK-001, and SEO-001 produce SPEC 21-compliant, traceable results with complete rule coverage and stable finding fingerprints.

**Architecture:** Keep rule evaluation pure in `src/lib/rules/p1.ts`; it emits stable classification codes, normalized causes, and narrowly scoped evidence. The worker groups those results into one rule execution per planned rule, derives SHA-256 fingerprints from the scan context, and aggregates repeated broken-link targets without treating failed collection as a clean result.

**Tech Stack:** TypeScript, Node.js built-in `crypto`, `node:assert/strict`, pnpm 11.1.1.

**Spec:** `D:\work\evalez\evalez-mvp-plan\tasks\T12-rule-model.md`; `D:\work\evalez\evalez-mvp-plan\referencias\evalez_SPEC_V3.0.txt` sections 8, 8.1, 15, 21.1, 21.2, and 26.2; `D:\work\evalez\evalez-mvp-plan\referencias\revision_PM_2026-10-28.pdf` findings A1 and A2.

## Global Constraints

- Use stable machine-readable codes; Spanish prose belongs only in rule summaries and contracts, not in the future UI.
- A failed, blocked, or omitted collection must never be recorded as a successful no-anomaly result.
- Fingerprints are exactly `sha256(organizationId|websiteId|ruleId|host|causeKey)`; volatile evidence is excluded.
- Do not persist new fields (T13), alter the report UI (T16), add rules, deploy, or contact external sites.
- Keep edits within T12-owned files, plus the minimal compile-only consumers named by T12.

## Review Focus

- A certificate whose `notBefore` is after `observedAt` must be a TLS finding; test it in Task 1.
- A TLS transport/probe failure must be blocked with its failure reason, never a missing-certificate finding; test it in Task 1.
- A 500, timeout, or missing internal-link response must be a failed check, not a passed target; test it in Task 1.
- Multiple LINK-001 observations for one broken target must produce one finding with all source paths; test it in Task 2.
- A missing homepage result must still produce all three planned rule executions and zero successful SEO/LINK checks; test it in Task 3.
